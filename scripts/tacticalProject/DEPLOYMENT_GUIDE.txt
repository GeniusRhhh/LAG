【敌方AI异常下降排查系统 - 完整部署指南】

======================== 核心理解 ========================

用户需求：不是仿真时间，而是**代码执行流程**
- 什么时候进入了DESCEND动作？  
- 哪个函数触发了下降命令？
- 为什么选择了这个下降的决策？
- 完整的调用链是什么？

我已为你构建了一套追踪系统来回答这些问题。

======================== 快速启动 ========================

【第1步】设置环境变量

在你的运行环境中设置：
  
  set ENEMY_DESCENT_DEBUG=1
  set CAP_ROOTCAUSE_TRACE=1
  set CAP_DEBUG_PRINT=1

或者执行：
  D:\Pycharm\LAG\scripts\tacticalProject\enable_descent_debug.bat

【第2步】运行仿真

  cd D:\Pycharm\LAG\scripts\tacticalProject
  python .\run_cap_simulation_native.py

运行时，调试信息会同步写入日志文件。

【第3步】分析日志

仿真完成后，查看生成的日志：

  .\cap_results\descent_debug.log

这个文件包含完整的决策链和执行过程。

======================== 日志文件说明 ========================

1️⃣  descent_debug.log (最重要)
   ────────────────────────────────────
   包含每一帧的完整追踪：
   
   [决策追踪] T=476.0s | B0200 @14458m 
   phase=INTERCEPT | mode=NEUTRAL
   threat_level=MODERATE | distance=50000m
   ┌─ 选择的动作: DIVE_ESCAPE
   ├─ 原因: 威胁接近需要规避
   ├─ 高度命令索引: 0
   └─ 高度变化: -300.0m
   
   ⇒ 下降发生
   is_descent=True
   descent_magnitude=300.0m
   previous_altitude=14758m
   
   这个文件就是完整的"函数调用链"原始记录。

2️⃣  descent_diagnosis.log
   ────────────────────────────────────
   系统初始化和配置记录
   
3️⃣  descent_trace_detailed.log
   ────────────────────────────────────
   动作选择的权重细节、状态转换原因等

======================== 追踪流程示例 ========================

【追踪B0200在t=476s的下降】

1. 打开 descent_debug.log

2. 搜索 "T=476" 和 "B0200":
   
   Select-String "T=476.*B0200" .\cap_results\descent_debug.log

3. 找到这一帧的完整信息:

   [决策追踪] T=476.0s | B0200 @14458m
   phase=INTERCEPT | mode=NEUTRAL
   threat_level=MODERATE
   selected_action=DIVE_ESCAPE        ← 选择了下降
   altitude_cmd_idx=0
   command_delta_altitude=-300.0m     ← 下降300米
   is_descent=True

4. 这就是答案：
   ✓ 时间: T=476s
   ✓ 智能体: B0200
   ✓ 动作: DIVE_ESCAPE (俯冲脱离)
   ✓ 原因: 威胁接近(threat_level=MODERATE)
   ✓ 命令: altitude_cmd_idx=0 (对应高度增量=-300m)
   ✓ 结果: 从14458m下降到14158m

5. 进一步追踪:
   
   a) 为什么选择DIVE_ESCAPE?
      → 查看动作权重日志
      → 搜索 "available_actions" 或权重列表
   
   b) 函数执行过程?
      → 查看 "FUNC_EXEC.*_execute_dive_escape"
      → 看参数和返回值
   
   c) 命令如何转换?
      → 查看 "ALTITUDE_CMD"
      → 看从action到具体cmd_idx的过程

======================== 关键搜索命令 ========================

【PowerShell】

# 1. 找B0200的所有下降
Select-String "B0200" .\cap_results\descent_debug.log | `
  Select-String "is_descent=True"

# 2. 找最大下降事件 (前5个)
Select-String "descent_magnitude" .\cap_results\descent_debug.log | `
  Sort-Object { [float]($_ -replace ".*magnitude=([0-9.]+).*", '$1') } -Descending | `
  Select-Object -First 5

# 3. 追踪特定时间
Select-String "T=476" .\cap_results\descent_debug.log

# 4. 找所有DESCEND和DIVE_ESCAPE
Select-String "DESCEND_ACTION|DIVE_ESCAPE" .\cap_results\descent_debug.log

# 5. 查看决策过程
Select-String "选择的动作|selected_action" .\cap_results\descent_debug.log | `
  head -50

【CMD或批处理】

REM 查找B0200的所有下降
findstr "B0200" cap_results\descent_debug.log | findstr "is_descent=True"

REM 查找DESCEND
findstr "DESCEND_ACTION" cap_results\descent_debug.log

REM 查看前100行
type cap_results\descent_debug.log | more

【故障排查】

问题: 日志没有生成
━━━━━━━━━━━━━━━━━━━
检查清单:
  1. ENEMY_DESCENT_DEBUG 环境变量是否设为 '1'?
  2. cap_results 目录是否存在?
  3. 仿真是否真的运行了?
  4. 权限是否足够写入文件?

问题: 日志内容为空
━━━━━━━━━━━━━━━━
原因可能:
  1. 敌方AI没有被调用
  2. 所有enemyai都在RETURNING状态
  3. 调试代码没有正确插入

解决:
  1. 检查敌方是否活着: Select-String "alive" cap_results\descent_debug.log
  2. 检查状态: Select-String "phase=" cap_results\descent_debug.log
  3. 重新应用补丁: python apply_descent_debug_patch.py

问题: 下降不在预期的时间
━━━━━━━━━━━━━━━━━━━━━━━
追踪步骤:
  1. 找到实际下降时间: Select-String "is_descent=True" cap_results\descent_debug.log
  2. 检查那时的决策: Select-String "T=那个时间" cap_results\descent_debug.log
  3. 看selected_action是什么
  4. 追踪为什么选择了那个动作
