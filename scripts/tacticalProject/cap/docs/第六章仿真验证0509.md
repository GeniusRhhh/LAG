第六章  基于战术规则模板的分层战术决策方法

6.1 引言
战术决策是空战系统的核心智能，需要在复杂多变的战场环境中实时选择最优的战术模板。本章建立完整的战术决策框架，包括态势评估、威胁评估、战术决策、机动决策以及参数决策。
6.2战术决策算法设计
6.2.1 决策层次体系
战术决策系统分为四个层次，按照"策略→战术→机动→参数"的顺序进行：
（1）策略决策：确定我方作战意图（激进肃清/保守肃清/防御/脱离）。
（2）战术决策：从战术库中选择战术模板（拖曳射击/钳形夹击/上下夹击/前后攻击/并排射击），每个模板包含预定义的机动序列。
（3）机动决策：负责传感器驱动的战术打断与核心任务执行保障。战术模板的机动序列在设计阶段已经确定（如钳形夹击战术的相应机动动作已预定义），机动决策层的作用不是选择机动原语，而是基于ECM、RWR、RADAR等传感器实时信息，在危急情况下根据策略类型（激进或保守）进行战术打断判断。同时，该层负责确保各控制距离节点核心任务的精确执行：MTR节点的攻击占位、LR节点的中制导照射（包括稍微偏置引导导弹直到末制导）、TR节点的规避转换、DOR节点的威胁分析与队形预调整、DR节点的Beam机动与战术计算、MAR节点的脱离机动。该层通过传感器融合与任务导向的微调机制，在保证战术连续性的前提下确保核心任务的安全有效完成。
（4）参数决策：确定机动参数（如Crank角度、速度增量、高度变化等）。
根据决策内容的重要性，战术控制距离被划分为四个等级：
	一级控制距离（NLT）：执行策略决策+战术决策+机动决策+参数决策。
	二级控制距离（MELD、DOR、DR）：执行战术决策+机动决策+参数决策。
	三级控制距离（MTR、TR、MAR）：执行机动决策+参数决策。
	四级控制距离（LR）：执行机动决策+参数决策。

6.2.3战术模板选择机制
战术模板的选择遵循以下流程：
（1）触发：当敌我距离穿越战术控制距离阈值时，启动决策流程。
（2）意图识别：预测敌方意图（攻击/中立/脱离）。
（3）态势评估：计算当前战场态势（优势/均势/劣势）。
（4）决策查表：根据当前控制距离、我方意图、敌方意图、战场态势，查询决策表，得到候选战术模板集合。
（5）模板选择：采用层次化决策算法，结合规则引擎和优化策略选择最优战术模板。
（6）模板实例化：加载选定模板的状态空间S、决策策略Π、参数集Θ。
（7）执行：模板通过状态转移函数δ自动推进战术阶段，直到下一个控制距离触发新的决策。
在模板选择中，采用层次化决策树结构，具体算法流程如下：

6.2.4传感器驱动的战术调整机制
本节设计机动决策层的核心算法，解决"是否需要打断或调整当前战术执行"的问题。该算法基于实时传感器信息（ECM、RWR、RADAR）进行战术打断判断，体现传感器驱动的智能决策机制。传感器信息融合机制如下：
RWR（雷达告警接收机）信息：实时监测敌方雷达辐射特征，识别威胁等级（0-5级）。当RWR告警等级≥4时，触发高优先级防御机动；等级≥3时，调整当前机动参数以增强规避效果。
ECM（电子对抗）信息：根据干扰效果评估敌方雷达性能，动态调整机动幅度。ECM激活时，可适当减小规避机动幅度；ECM失效时，增大机动幅度并优先选择物理规避。
机载雷达信息：提供敌机位置、速度、航向等运动参数，用于预测敌机意图和优化机动时机。雷达失锁时，立即转入保守机动模式。
每个战术模板在设计阶段预定义了核心机动序列，但执行过程中基于威胁评估进行实时调整。系统采用分层打断逻辑：
（1）一级打断（立即执行）：检测到导弹发射或RWR告警≥5级时，无论当前策略类型，立即中断战术执行，转入战术规避。
（2） 二级打断（条件执行）：RWR告警等级4级或敌机进入MAR距离时，根据我方策略决定：激进策略继续当前战术但调整参数；保守/防御策略转入战术回转。
（3）三级调整（参数优化）：RWR告警等级2-3级时，保持当前战术但优化机动参数，如增大Crank角度、提前执行Short Skate等。
决策优先级排序：生存 > 任务完成 > 战术连续性，确保在危急情况下优先保存实力。

46: end switch

6.2.5自适应参数计算机制
本节设计参数决策层的核心算法，解决"为确定的机动原语计算具体数值参数"的问题。该算法考虑威胁等级、角色分工、机动类型等多种因素，实现参数的自适应计算。
参数计算的关键考虑因素：威胁等级：根据当前威胁程度调整机动参数的激进程度；角色分工：长机和僚机采用不同的参数策略；机动类型：针对不同机动原语进行专门的参数优化；中制导约束：考虑导弹中制导阶段对飞机机动的约束要求；飞行包线：确保所有参数都在安全飞行范围内。
算法6.4 机动参数计算算法
算法6.4 机动参数计算算法
Input: m (机动原语), threat_level (威胁等级), role (角色), rel_state (相对态势)
Output: θ* (优化参数集)


1:  // 获取基础参数模板
2:  θ_base ← GetDefaultParameters(m)
3:  
4:  // 威胁等级自适应调整（基于6.3节威胁评估公式）
5:  threat_level ← 0.4×RWR_threat + 0.3×missile_threat + 0.2×radar_threat + 0.1×range_threat
6:  if threat_level > 0.7 then
7:      θ_base.amplitude ← θ_base.amplitude × 1.5  // 增大机动幅度
8:      θ_base.duration ← θ_base.duration × 0.8    // 缩短机动时间
9:  else if threat_level < 0.3 then
10:     θ_base.amplitude ← θ_base.amplitude × 0.7  // 减小机动幅度
11: end if
12:
13: // 角色差异化配置
14: if role = "长机" then
15:     θ_base.risk_tolerance ← 0.7  // 更激进的参数
16: else  // 僚机
17:     θ_base.risk_tolerance ← 0.5  // 更保守的参数
18: end if
19:
20: // 机动特定参数优化（考虑中制导需求）
21: if m = B then  // Crank机动
22:     if d = "LR" ∧ radar_guidance_active then
23:         θ_base.crank_angle ← min(θ_base.crank_angle, 30°)  // 限制角度保持照射
24:     else if rel_state.bearing > 30° then
25:         θ_base.crank_angle ← θ_base.crank_angle + 15°
26:     end if
27:     if rel_state.closing_rate > 200 then
28:         θ_base.duration ← θ_base.duration - 2.0
29:     end if
30: else if m = C then  // 平飞机动（中制导保持照射）
31:     if d = "LR" then
32:         θ_base.duration ← GetGuidanceDuration()  // 导弹中制导时间
33:         θ_base.heading_stability ← 0.95  // 高稳定性要求
34:     else
35:         θ_base.duration ← GetPhaseDuration(当前阶段)
36:     end if
37: else if m = K then  // Short Skate机动
38:     θ_base.escape_direction ← ComputeOptimalEscape(rel_state)
39:     θ_base.escape_angle ← 90°  // 标准侧向规避
40：end if
41：
42：// 飞行包线约束检查
43：θ* ← ApplyFlightConstraints(θ_base)
44：// 约束条件：高度≥安全高度，速度在[Vmin, Vmax]范围内
45：return θ*
该算法实现了参数决策层的核心功能，为确定的机动原语计算具体的执行参数。算法具备威胁自适应能力，能够根据威胁等级动态调整机动参数的激进程度和风险容忍度，同时通过角色差异化设计使长机和僚机采用不同的参数策略，充分体现编队协同的差异化分工。针对不同机动类型如Crank、平飞、Short Skate等，算法进行专门的参数优化，特别考虑了导弹中制导阶段对飞机机动参数的约束要求，使得飞机能够稍微偏转指引方向以满足中制导需求。算法还通过包线约束机制确保所有参数都在飞行器的安全飞行范围内，从而完成了从抽象机动意图到具体数值参数的精确映射。
6.2.6决策系统集成与调用流程
本节描述四个决策层次的统一调用流程和系统集成机制，使各算法协调工作，形成完整的战术决策系统。四个决策层次的算法映射：
（1）策略决策：通过5.2.2节的三要素分析确定我方意图（在NLT距离确定）。
（2）战术决策：算法6.1 - 在控制距离节点选择战术模板T（每个模板包含预定义机动序列）。
（3）机动决策：算法6.3 - 基于传感器信息判断是否打断当前战术T，进行战术调整。
（4）参数决策：算法6.4 - 为当前执行的机动计算具体参数θ（基于威胁等级、角色等）。
需要注意的是，每个战术模板在设计阶段已预定义了固定的机动序列，因此机动决策的作用不是选择机动原语，而是基于传感器信息（ECM、RWR、RADAR）进行战术打断和执行调整。
整个决策系统按照策略、战术、机动、参数的层次顺序依次执行。策略决策层在到达NLT控制距离时启动，基于5.2.2节的三要素分析确定我方作战意图，输出激进肃清、保守肃清、防御或脱离等意图类型。战术决策层在到达关键控制距离节点（NLT、MELD、DOR、DR）时触发，调用算法6-1进行战术模板选择，输出最优战术模板及其实例化参数。机动决策层具有最高的响应优先级，在传感器状态变化或到达控制距离节点时立即触发，调用算法6-2进行传感器驱动的战术打断判断与核心任务执行保障，根据ECM、RWR、RADAR信息和策略类型（激进或保守）决定是否在危急情况下打断当前战术，同时通过微调机制确保各节点核心任务的精确完成。参数决策层在机动原语确定后、具体执行前进行参数计算，调用算法6-4根据威胁等级、角色分工等因素输出优化的机动参数集。

6.3仿真验证

为验证本文 4 机对 4 机 CAP 协同空战方法在不同风险等级下的真实表现，本节把验证重点放在四条证据链上：其一，协同探测与协同跟踪能否在真实对抗中形成可交战火控条件；其二，控制距离推进与战术模板切换是否与初始几何、风险等级和敌方行为演化保持一致；其三，发射门、接力制导、意图识别与任务威胁评估是否真正介入交战过程；其四，责任区风险图能否跟随真实威胁占用变化而保持可用的一致性。

巡逻任务状态包括巡逻（Patrol）、截获（Intercept）、交战（Engage）、规避（Evade）和返航（Return to Base），描述的是联队层总体任务姿态。控制距离阶段包括远距接敌段（BEYOND_NLT）、NLT 向 MELD 压缩段（NLT_MELD）、MELD 向 MTR 压缩段（MELD_MTR）、MTR 向 LR 推进段（MTR_LR）、LR 向 TR 推进段（LR_TR）、TR 向 DOR 脱离准备段（TR_DOR）、DOR 向 DR 再压缩准备段（DOR_DR）、DR 向 MAR 临界规避强化段（DR_MAR）以及后期整理段（BEYOND_MAR）。

核心战术模板仍包括拖曳射击、钳形夹击、高低配合、前后攻击、并列攻击、战术规避和战术转向；仿真中额外出现的自适应攻击、防御守区、统一二次攻击等标签，可理解为执行层运行态，而不是新增理论模板。

（3）协同探测、协同跟踪与接力制导分析

图6-2 场景一协同探测与跟踪链时序

图6-2反映出场景一的协同探测节奏整体偏稳，但并不激进。4 架友机雷达于 80.2 s 至 102.0 s 之间完成接手，激活均值 94.55 s、标准差 8.86 s，说明系统并未出现明显失步。目标首探延迟均值 7.9 s，最慢目标 B0400 也仅比最早激活时刻滞后 17.4 s，因此探测闭合本身并不是场景一的瓶颈。

真正的问题出现在“闭合之后”的持续质量上。激活后平均探测覆盖率只有 42.00%，全覆盖连续性仅 2.00%，而任意目标连续性却达到 90.00%。这意味着系统在场景一中优先保证了“总有关键目标不断链”，却很难长时间同时维持四目标稳定覆盖。对于低风险样本而言，这种结构会导致火控链可以建立，但难以持续维持高质量的多目标支撑。

图6-3 场景一协同跟踪、发射门与接力制导时序

图6-3进一步说明了探测链、跟踪链与发射链之间的真实先后顺序。场景一在 203.4 s 才形成首次稳定双机就绪，在 279.6 s 才第一次通过发射门，在 296.8 s 才出现首次接力制导成功，说明发射并非由探测完成直接触发，而是要等到稳定双机跟踪和几何条件共同满足之后才开放。

但从后段表现看，这条链路的“通过”与“兑现”之间存在明显损耗。场景一发射门累计通过 11 次，接力制导尝试高达 2505 次，最终成功仅 18 次，成功率 0.72%。这说明当前系统可以在低风险场景下维持很长的接力工作时间，但接力质量并不高，发射后中制导阶段仍然存在较多几何退化和照射丢失。

图6-4 场景一发射门与接力制导累计曲线

图6-4揭示了场景一的另一项关键特征：发射门虽然严格，但并不代表发射链高效。场景一发射门通过率 2.20%，看似高于场景二、场景三，但它对应的是更长的交战拉扯和更多的后段窗口，而非更高的单位机会效率。与之对应，友方未命中主因由 `distance_increasing` 和 `illumination_lost` 各 4 次共同构成，说明低风险场景的主要短板不在“能否发现目标”，而在“发射后是否能把目标持续压在有利几何中”。

（3）协同探测、协同跟踪与接力制导分析

图6-13 场景二协同探测与跟踪链时序

图6-13首先表明，场景二的探测链具有明显的搜索恢复特征。20 s 左右预警机失效后，系统从 `DIRECTED` 切入 `SWEEP`，随即触发 `SEARCH`。尽管如此，首次雷达航迹仍在 36.8 s 建立，68.8 s 完成全探。也就是说，场景二验证的不是理想条件下的协同探测，而是“预警机失配后是否还能靠机载雷达重新闭合目标集”。从结果看，这一能力已经具备。

不过，探测覆盖质量不能简单看全探完成时刻。场景二激活后平均探测覆盖率只有 20.00%，全覆盖连续性为 0.00%，任意目标连续性为 69.20%。这意味着虽然系统可以在关键时刻把 4 个目标重新找出来，但很难长期同时稳态覆盖四目标。场景二能够维持 4 个稳定跟踪目标峰值，依赖的更像是多机交替接手与局部重构，而不是持续静态全覆盖。

图6-14 场景二协同跟踪、发射门与接力制导时序

图6-14显示，场景二在 152.2 s 形成首次稳定双机就绪后，直到 232.0 s 才放行首次发射门，248.0 s 才出现首次接力制导成功。相比场景一，场景二在跟踪峰值和稳定就绪上更好，但从首杀时间看却更慢：首次敌机击落直到 615.2 s 才出现。这说明当前中风险持续压制样本的难点不在于“火控条件能否搭起来”，而在于“搭起来以后能否快速兑现杀伤”。

图6-15 场景二发射门与接力制导累计曲线

图6-15把这个问题进一步量化。场景二发射门通过 13 次，总请求 1214 次，通过率仅 1.07%；接力制导尝试 1970 次，成功 20 次，成功率 1.02%。友方未命中主要原因集中在 `illumination_lost`（7 次），其次才是 `distance_increasing`（2 次）。这表明场景二的主瓶颈已经从几何拖尾转移到照射维持：系统可以抓住窗口发射，但在中段持续压制和感知波动条件下，照射链更容易断裂。

（4）场景二全过程交战分析

图6-16 场景二任务状态、战术模板与控制距离阶段时序

图6-16说明，场景二的战术组织呈现“宽正面压制 + 长时间守区”的特征。左路主要由 `SIDE_BY_SIDE`、`ADAPTIVE_ATTACK` 和 `DEFENSIVE_GUARD` 组成，右路也以 `SIDE_BY_SIDE` 和 `DEFENSIVE_GUARD` 为主。这与场景一前后攻击/并列攻击的异步组合不同，场景二更倾向于在中风险压力下维持较宽横向正面，再通过自适应攻击和守区把交战拖入可控残局。

图6-17 场景二控制距离动态演化

图6-17与表6-23共同表明，场景二左右两路的推进节奏差异显著。左路在 70.4 s 即进入 NLT_MELD，而右路要到 98.2 s 才进入同一阶段；右路虽然较晚启动压缩，但在后段更早穿越 DR_MAR 和 BEYOND_MAR，这说明系统并没有强制双路同步，而是在持续压力下允许一侧负责压制、一侧负责残局整理。

图6-18 场景二敌我存活数与剩余导弹变化

场景二的击落时间线非常典型地体现了“右路成为主杀伤通道”。A0100 在 615.0 s 击落 B0100，B0100 随后于 648.6 s 反击击落 A0100；从 667.2 s 开始，A0300 先后击落 B0300、B0400 和 B0200，最终实现 4:1 的战果。需要强调的是，虽然敌机在 1111.2 s 已全部被歼灭，但任务结果字段仍停留在 `in_progress`。这并不表示战术失败，而是暴露出任务结果结算逻辑对“最后一击发生在仿真尾端”的收敛仍不充分。

总体上看，场景二是本批次综合效果最好的样本：它在预警机失效 370 s 的条件下仍完成四目标击落，仅损失 1 架友机，并且把稳定双机峰值和稳定跟踪峰值都拉到 4。换言之，当前系统在“中风险持续压力 + 信息不完整”这一更贴近实战的条件下，反而展现出了更强的综合韧性。

（5）场景二意图识别与风险区控制分析

图6-19 场景二联队级意图识别总览

图6-19显示，场景二的任务高威胁在 108.4 s 就已出现，而首次高威胁意图直到 190.0 s 才出现，说明在这一场景中，任务层威胁评估仍然领先于意图解释。与场景一不同，场景二的高威胁更多由持续压制和感知缺口触发，而不是由单次残局交汇触发，因此任务层高威胁对早期战术切换的驱动更直接。

图6-20 场景二逐目标意图时间线

图6-20最值得关注的目标是 B0200。该目标标签切换达到 36 次，威胁切换 38 次，是本批次最不稳定的单目标样本之一。这反映出在中风险、信息不完整和长时间拉扯条件下，意图识别输出会显著放大目标行为波动。也正因如此，场景二更适合用来检验“意图模块是否能跟住复杂行为变化”，而不是检验“意图标签能否很快收敛到固定终值”。

图6-21 场景二逐目标威胁等级与置信度

从图6-21可以看出，场景二四个敌目标都进入过 critical 峰值，但持续时间和切换频率差异很大。这说明中风险持续压制场景的关键不在某一目标瞬时最危险，而在多目标危险程度交替上升、下降并反复切换。对于责任区控制而言，这比单次高风险突防更难处理，因为它要求系统持续修正资源分配而不是做一次性快速响应。

图6-22 场景二风险区计数曲线

图6-22从风险区角度验证了这一点。场景二真实中风险区占用时间达到 1016.8 s，而图像侧仅记录 436.4 s；期望风险区图真一致率只有 19.42%，全风险区精确一致率 12.94%。也就是说，系统在实际交战层面已经能赢，但在“把持续中风险压力完整映射进责任区图”这一层面仍然明显偏弱。这是当前版本最明确、也最具工程价值的短板之一。

图6-25说明，场景三在 31.8 s 就建立首次稳定双机就绪，106.2 s 开放首次发射门，131.2 s 产生首次接力制导成功。值得注意的是，首次扫描分配反而要到 303.6 s 才出现。这一现象表明，在高风险近距离场景中，系统更多依赖“直接锁定和即时交战”而非传统意义上的从容扫描分配，扫描分配成为后续稳态支撑工具，而不是开局前置条件。

图6-26 场景三发射门与接力制导累计曲线

图6-26显示，场景三在高压条件下把接力制导效率推到了本批次最高：接力制导成功 35 次，成功率 1.86%，明显高于场景一和场景二。发射门通过率为 1.26%，并没有因为风险更高而无限放宽，说明高风险响应的本质不是“粗暴放行”，而是“在更前的位置、更早的时间点建立可用火控并尽快兑现”。

（4）场景三全过程交战分析

图6-27 场景三任务状态、战术模板与控制距离阶段时序

这一结果与场景二形成鲜明对照：场景三更快、更前、更激烈，但不一定更经济。我方最低速度下探至 77.90 m/s，友机仿真重建 21 次，说明高风险压缩下的能量与飞行包线压力极大。当前系统已经能够在这种极端条件下抢先开火并完成清场，但还无法把损失有效压低。

（2）战术决策算法与控制距离推进算法有效性分析

本批次结果表明，战术决策算法已经能够依据场景压力形成明显不同的执行路径。场景一从低风险正面对进起步，却没有维持成简单保守模板，而是演化为左路前后攻击、右路并列攻击并在中后段转入守区；场景二在持续中风险压力下更倾向于双路并列压制和长时间防御守区，体现出对持续不完整信息的稳态应对；场景三则在极短时间内完成高风险前置响应，先形成前后攻击/钳形夹击的快速组织，再迅速切换到守区和残局压缩。这说明模板选择已经不是单一风险等级到单一战术名的硬映射，而是能反映不同几何和压力结构。

控制距离推进算法也得到了更清晰的验证。场景一、场景二的动态节点与理论节点完全一致，说明系统在中远距样本中保持标准控制距离集；场景三则把 NLT 压缩到 141.8 km、TR 压缩到 63.0 km、MAR 压缩到 27.6 km，清楚体现出高风险场景的前移约束。更重要的是，三个场景中首次发射门通过都早于某些路径正式进入 TR_DOR，这证明发射门不是简单地绑定某个距离标签，而是由节点参照、稳定跟踪和实时生存性共同决定。换言之，控制距离算法当前已经具备“场景自适应求参 + 过程异步推进”的基本正确性。

从效果上看，本批次并不支持“风险越高越差”或“风险越高越好”这类线性结论。场景二的中风险样本给出了最佳综合交换比，场景三给出了最快反应和最完整清场，场景一则展示了低风险自由博弈下更充分的链路拉伸过程。这一结果反而更有价值，因为它说明当前算法已经进入“真实可观测”的阶段，而不是停留在脚本示例阶段。

（3）协同探测、协同跟踪与接力制导算法有效性分析

协同探测算法在三场景中都能形成可靠闭合，但性能侧重点已经明显分化。场景一的探测链稳健，持续全覆盖能力相对保守；场景二在预警机长时间失配下仍能恢复全探，说明搜索恢复能力已经具备；场景三把探测链前置到 3.6 s 内完成，说明系统可以在高压环境下把感知资源迅速集中。对论文验证而言，这比简单比较“哪个场景更快”更重要，因为它表明探测算法已经具备对不同压力结构的适应性。

协同跟踪算法的有效性，则体现在“稳定就绪峰值”和“稳定跟踪峰值”的跨场景差异上。场景二能把两项峰值都拉到 4，是当前最完整的多目标稳定火控样本；场景三虽然更快，但稳定双机峰值只有 3，说明极端高压下系统优先保证反应速度，而不是长期维持完美双机结构；场景一则只达到峰值 2，这恰好解释了为何它虽然能交战，却很难在后段维持低损耗收口。

接力制导算法已经不再是“有没有成功次数”的装饰指标，而是真正参与了战果兑现。场景一体现出长尾交战中的持续工作能力，场景二体现出照射维持对中风险压制的重要性，场景三则在高压样本中取得了最高接力成功率 1.86%。从导弹结束原因看，友方未命中在三个场景中分别体现为：场景一 `distance_increasing` 与 `illumination_lost` 并重，场景二以 `illumination_lost` 为主，场景三则同时出现 `guidance_timeout`、`illumination_lost` 和 `distance_increasing`。这说明当前系统对“发射后保持有利几何和照射链”的提升方向已经非常明确。

（4）意图识别、威胁评估与风险区控制算法有效性分析

本批次意图识别模块最大的变化，是原始输出时刻显著前移。三个场景的原始意图输出都在 0.2 s 出现，稳定就绪都在 6.4 s 完成，说明在线适配器已经能够在仿真开局立即给出行为推断候选。真正有分析价值的差异体现在“首次高威胁意图”与“任务高威胁”的相对关系：场景一中高威胁意图略早于任务高威胁，场景二中任务高威胁明显早于高威胁意图，场景三则二者同步。这说明当前版本里，意图与任务威胁已经不再保持固定先后关系，而是受场景结构本身影响。

风险区控制方面，本批次也给出比早期样本更真实的结论。三个场景的全风险区精确一致率都在 11%–13% 左右，说明系统当前更擅长把握主风险方向，而不是逐像素精确拟合所有细粒度区域；但场景一和场景三在期望风险区上能保持 50% 左右的一致率，已经足以支持“知道风险主要落在低/高哪一层”的方向性判断。最值得继续强化的部分集中在场景二：持续中风险压力虽然被系统有效处理，却还没有被风险图完整刻画出来。对于论文结论而言，这意味着风险区算法已经具备任务层触发价值，后续可继续朝全过程细调度能力推进。

另一个不能忽略的事实是任务结果结算。场景二和场景三都实现了敌机全灭，但结果字段仍停留在 `in_progress`。这说明任务状态机对“战术上已胜、状态上未收敛”的末端处理仍可进一步完善。该问题不影响本文对探测、决策和交战链有效性的判断，但会直接影响自动化评估和实验批处理统计的一致性，值得作为后续工程修正项单独处理。

（5）本章算法的综合结论与后续改进方向

综合三场景结果，可以得出以下结论。第一，当前方法已经能够在低、中、高三类风险条件下建立完整的“探测—跟踪—发射门—接力制导—战果兑现”链路，说明本章算法具备真实运行基础。第二，战术决策与控制距离推进已表现出明确的场景适应性：中远距样本保留标准节点集，高风险低空突防样本则自动前移节点并提早进入交战。第三，综合效费比最优的不是最快的高风险样本，而是中风险持续压制样本；这表明当前系统已进入真实工程优化阶段，性能不再由单一“快慢”决定，而由感知韧性、照射持续、残局组织和飞行包线共同决定。第四，风险图和任务结果字段相对慢于交战链本身的成熟度，是本批次最值得优先继续优化的两个系统级环节。

基于上述结论，后续改进建议聚焦于三点。其一，围绕 `illumination_lost` 与 `distance_increasing` 优化中制导阶段的几何保持和照射交接，提高接力制导的真实毁伤效率。其二，增强风险区算法对持续中风险压力的长时占用刻画能力，进一步缩小“交战表现”和“图像刻画”之间的差距。其三，修正任务结果状态机的末端收敛逻辑，使敌机全灭这类明确战术结果能够及时映射到任务结果字段。
