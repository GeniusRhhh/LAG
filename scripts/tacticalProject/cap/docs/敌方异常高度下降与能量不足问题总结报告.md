二、问题概述

当前问题表现为敌方飞机在交战过程中出现速度持续下降、高度持续下降、后期能量耗尽，严重时进入不可恢复的异常飞行链路。

根据多轮日志复盘，问题并非单一故障，而是由以下几部分共同构成：

1. 高层正常战术阶段存在持续耗能的离散命令组合。
2. 底层 baseline_model.pt 不具备能量自保能力，只会忠实执行上层命令。
3. 返航阶段在低速区缺少足够的止沉与保速保护。
4. 新增恢复层虽然方向正确，但仍存在误判、漏判和补偿方向不合适的问题。
5. 敌机运行链路中缺少中途自动 RNN 重置，恢复前后的隐状态处理不合理。

结论：

桥接更稳定，主要原因不是动力学变化，而是控制源稳定、任务模板单一。
非桥接更容易掉高，主要原因是战术状态机之间容易发生控制冲突和重入。

七、对当前主根因的最终判断

综合前述样本，当前最稳妥的总判断如下：

根本原因不是单一 bug，而是高层战术层和底层模型层之间的契约设计错误。

更具体地说：

高层在正常战术阶段持续发出耗能离散命令。
底层 baseline_model.pt 不具备能量自保能力，只会忠实执行。
因此飞机在进入任何保护层之前，就已经把能量耗掉。

这也是前期已经增加包线保护、恢复层、硬恢复、舵面限制之后，问题仍无法彻底消失的根本原因。因为这些修改主要解决的是

掉速之后如何止损

而真正致命的问题是

为什么在正常阶段会持续掉速

八、RNN 重置机制现状与合理性判断

1. 当前到底有没有 RNN 重置机制

结论：

代码层面有。
敌机 B0100 当前实际运行层面，基本等于没有自动中途重置。

表现为：

episode 开头会清零，这一部分合理。
手工接口可以 reset，这一部分合理。
敌机在中途异常恢复时，没有自动 reset。

对应日志文件：

cap_20260403_200059.log

2. 当前为什么说不合理

原因如下：

进入 HARD_RECOVERY 时，模型被 bypass，但 RNN 状态既不清零，也不更新。
恢复持续很久后，一旦重新接回模型，接回的仍是恢复前那一刻的旧 hidden state。
旧 hidden state 可能保留错误的战术与姿态上下文。
退出恢复后，模型容易再次滑回原有异常趋势。

结论：

RNN 不自动 reset 不是第一根因，但它会放大恢复困难，使恢复后的重新接管更加不稳定。

对应日志文件：

cap_20260403_200059.log
cap_20260403_193504.log

十、后续真正的根治方向

当前结论已经比较明确，继续只修 HARD_RECOVERY 和末端包线，收益会越来越有限。真正的根治方向应向前移动，核心应放在高层战术命令层。

建议的方向如下：

1. 在高层命令输出后增加战术前能量门。
2. 抬高高空正常战术阶段的默认速度档。
3. 为高耗能动作增加低能量替身动作。
4. 保留现有恢复层与包线层，但只让其承担最后兜底角色。

其中最关键的是第一条，即在正常战术阶段先判断当前能量是否允许执行该动作，而不是等掉速之后再交给恢复层和硬恢复收尾。

十一、最终结论

通过对多份异常日志和正常对照日志的连续排查，可以形成如下最终判断：

1. 交战早期样本表明，拦截初段某些固定离散命令模板本身就带有下沉与耗能倾向。
2. 返航样本表明，飞机在低速区进入返航回转链后，现有返航函数和固定命令组合缺少足够止沉保护。
3. 新增恢复层样本表明，即使后端恢复逻辑开始接管，如果能量判定、分类与补偿方向没有收敛，仍会继续制造掉速。
4. 最新样本 cap_20260403_200059.log 进一步证明，飞机在进入任何保护层之前，就已经在正常战术阶段开始持续掉速。

因此，当前最准确的总定性应为：

敌方异常高度下降与能量消耗问题的根本原因，是高层战术函数在正常阶段持续下发耗能离散命令，而底层模型没有能量自保能力，导致飞机在进入保护层之前就先把能量耗掉。

恢复层、包线层、HARD_RECOVERY 仍然需要保留，但它们只能负责末端止损。真正的治理责任必须前移到高层战术命令生成阶段。
