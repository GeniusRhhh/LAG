# 协同探测算法审查与完善需求

## 1. 项目背景

### 1.1 用户问题

用户在审查协同探测算法实现时提出了以下关键问题：

1. **"集中扫描，资源共享到底是怎么实现的？看到日志记录里似乎扫描的都是同一块区域，这不就是重复了吗？"**
   - 用户发现所有飞机扫描同一区域，质疑是否浪费资源

2. **"如果有敌方在范围外呢？"**
   - 用户担心完全重叠的扫描策略无法处理预警机误差

3. **"都是从同一方位开始扫描，做重复动作，浪费时间怎么提高效率呢？"**
   - 用户质疑扫描效率问题

4. **"请你严格检查雷达硬属性是不能改的"**
   - 用户强调必须遵守雷达硬件约束（±10°/2s, ±30°/5s, ±60°/10s）

5. **"按照你的修改，现在探测延迟大幅提高，到底为什么，要用什么协同探测算法才是最好的啊"**
   - 用户发现探测延迟从2s增加到42s（20倍恶化）

6. **"让你多机协同探测算法设计与验证报告.md文档，看看里面的算法我是否均已实现并投入使用，如果没有，请为我投入使用。"**
   - 用户要求审查设计文档中的所有算法是否已实现

### 1.2 根本原因分析

通过代码审查发现：

**问题1：定向扫描算法实现错误**
- **错误实现**：所有飞机扫描中心完全相同（完全重叠）
- **正确要求**：应该略微分散（5°间隔），参考文档第4.2.3节
- **后果**：
  - 浪费雷达资源（4部雷达做同样的事）
  - 无法处理预警机2.5km误差
  - 有效覆盖范围仅20°，应该是35°

**问题2：雷达扫描范围选择错误**
- **错误实现**：使用±5°扫描范围（不存在的硬件参数）
- **正确要求**：必须使用±10°/±30°/±60°（雷达硬属性）
- **后果**：
  - 目标落在扫描范围外
  - 探测延迟从2s增加到42s（20倍恶化）

**问题3：算法实现不完整**
- 设计文档中定义了多个算法，但部分未实现或未投入使用
- 需要系统性审查所有算法的实现状态

### 1.3 参考文档

- **主文档**：`scripts/tacticalProject/cap/docs/多机协同探测算法设计与验证报告.md`
- **实现文件**：`scripts/tacticalProject/cap/tactics/cooperative_detection.py`
- **调用文件**：`scripts/tacticalProject/cap/cap_task.py`

## 2. 需求概述

### 2.1 核心目标

1. **修复定向扫描算法**：从"完全重叠"改为"略微分散"（5°间隔）
2. **修复雷达扫描范围**：严格使用雷达硬属性（±10°/±30°/±60°）
3. **审查算法实现状态**：检查设计文档中的所有算法是否已实现
4. **补充缺失算法**：实现设计文档中定义但未实现的算法
5. **验证性能指标**：确保探测延迟满足设计要求

### 2.2 成功标准

1. **定向扫描**：
   - ✅ 各飞机扫描中心分散5°
   - ✅ 有效覆盖范围扩大到35°（从20°）
   - ✅ 截获时间 <5s

2. **雷达硬属性**：
   - ✅ 只使用±10°/±30°/±60°扫描范围
   - ✅ 对应扫描时间：2s/5s/10s

3. **算法完整性**：
   - ✅ 设计文档中的所有算法均已实现
   - ✅ 所有算法均已投入使用

4. **性能指标**（参考文档第9.6节）：
   - ✅ DIRECTED模式截获时间 <5s
   - ✅ SWEEP模式截获时间 <50s
   - ✅ SEARCH模式重新截获时间 <30s

**需求ID**: FR-1  
**优先级**: P0（最高）

**详细要求**：
1. 实现分散公式（文档第4.2.3节）：
   ```
   δ_i = (i - (N-1)/2) × Δθ_spread

   ```

   ```
   scan_center_i = center_bearing + δ_i
   ```

4. 保持扫描时间：2s

### 4.4 跟踪质量评估算法

**需求ID**: FR-4  
**优先级**: P1（高）  
**状态**: 待实现

**描述**：实现跟踪质量评估算法（文档第7节）

**详细要求**：
1. 实现4个子指标：
   ```python
   f_update = min(1.0, N_update / 5.0)  # 更新连续性
   f_age = max(0.0, 1.0 - t_age / 30.0)  # 时效性
   f_distance = max(0.3, 1.0 - 0.7 * R / 200.0)  # 距离
   f_fusion = min(1.0, N_tracker / 2.0)  # 融合度
   ```
2. 计算综合质量指标（使用乘积）：
   ```python
   Q_track = f_update × f_age × f_distance × f_fusion
   ```
3. 判定发射条件：
   ```python
   is_ready = (Q_track >= 0.6)
   ```

**实现位置**：
- 新建文件：`scripts/tacticalProject/cap/tactics/track_quality.py`
- 或在现有文件中添加：`scripts/tacticalProject/cap/picture/track_fusion.py`
